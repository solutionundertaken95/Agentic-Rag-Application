# NovaRetail IT Service Desk Runbook

## Email Troubleshooting
- If a user cannot send or receive email:
  - Confirm whether the issue affects **one user or many users**.
  - Check **network connectivity** and the **service status dashboard**.
  - For a single user:
    - Sign out and back in.
    - Verify mailbox quota.
    - Test the web client.
  - For widespread incidents:
    - Do **not** ask each user to reinstall software.
    - Escalate the suspected service incident.

---

## Laptop Performance
- For a slow laptop:
  - Check CPU, memory, and storage free space.
  - Review startup applications.
  - Confirm operating system updates.
  - Verify endpoint security scan status.
- Do **not** disable security agents as a troubleshooting shortcut.
- Escalate when:
  - Hardware diagnostics report failure.
  - Repeated shutdowns continue after software remediation.

---

## Ticket Priority
- **P1**: Company-wide outage or critical security incident.  
- **P2**: Major team blocked with no workaround.  
- **P3**: Individual user blocked or degraded with limited workaround.  
- **P4**: Standard request, information request, or low-impact issue.  

---

## Remote Support
- Use approved remote support tools only.  
- Always request user consent before initiating a remote session.  
- End the session immediately if sensitive data is visible that is unrelated to troubleshooting.  
- Document actions taken during remote support in the ticket.

---

## Escalation Workflow
- Escalate to **Tier 2** when:
  - Issue persists after following Tier 1 troubleshooting steps.
  - Specialized system knowledge is required.
- Escalate to **Tier 3 / Engineering** when:
  - Root cause is traced to infrastructure or application code.
- Always include:
  - Ticket history.
  - Steps already attempted.
  - Logs or screenshots.

---

## Knowledge Base Usage
- Search the internal **Knowledge Base** before escalating.  
- Update KB articles when new fixes are discovered.  
- Flag outdated or incorrect KB entries for review.  
- Encourage self-service by linking KB articles in ticket responses.

---

## Incident Communication
- For **P1 incidents**, notify:
  - IT Manager
  - Security Team
  - Communications Team (for company-wide updates)
- Use the incident communication template:
  - Summary of issue
  - Impacted systems/users
  - Current status
  - Next update time
